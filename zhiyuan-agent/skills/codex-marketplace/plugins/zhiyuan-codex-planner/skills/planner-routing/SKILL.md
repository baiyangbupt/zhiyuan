> 本技能只负责**选路**，不负责回答。选定之后按那个技能的 SKILL.md 走。

# 智愿规划·入口与路由

## 适用条件

- 任何与高考志愿相关的用户消息，**包括看起来很简单的一句话问题**。
- 尤其是"哪个好 / 值不值 / 怎么选"这类**没有唯一实体、也没有给参数**的问题——
  这类最容易滑成"请先提供省份/分数"，而用户要的是先听到内容。

## 不适用条件

- 已经在某个阶段技能内部（它的流程没走完），不要中途重新选路。
- 纯寒暄、与志愿无关的问题：直接回答，不选路。

## 前置状态

- 无。任何阶段都能进入；本技能不读取任何业务状态。

## 允许能力

- 无。**路由技能不调工具**——一旦它开始查数据，它就不再是路由，而是替阶段技能做了一半的活。
- 需要工具的阶段交给选中的那个技能。

## Evidence 要求

- 无。路由不产出事实，因此不绑定 `evidenceRefs`。
- 但它必须**不谎称**有证据：路由句里不能出现分数、概率、录取结论。

## 单轮调用预算

- 工具调用 0 次。

## 标准步骤

1. **先说路由**：一句话讲清这轮按哪个技能走（如"这轮按院校专业探索走"）。说出来是为了让用户能纠正。
2. 按下表选**一个**技能，不并排展开两个：

   | 用户想干什么 | 走哪个 |
   |---|---|
   | 还没交代自身情况，或情况自相矛盾 | `profile-discovery` |
   | 想了解或**比较**院校、专业、城市、培养路径 | `school-major-exploration` |
   | 问录取分、招生计划、选科资格、能不能报 | `admission-fact-analysis` |
   | 要一批候选、要冲稳保 | `candidate-recommendation` |
   | 要把候选排成方案 | `plan-construction` |
   | 要终审已有方案 | `plan-final-review` |

3. **缺门禁事实不阻塞解释性内容**：省份/年份/成绩位次/选科/批次缺失时，
   阻塞的是**录取结论**（分数、概率、冲稳保、能不能报），不阻塞方向性解释与维度对比。
   两者要分开说：能说的先说完，再在最后问缺的那几项。
4. **交接要点名**：本轮结束时说明下一轮会走哪个技能、需要用户给什么。
   一轮只走一个技能，不要在同一轮里跨阶段。

<HARD-GATE>
判阶段用**快照字段**（`planningStage` / `allowedCapabilities`），不凭对话记忆猜；
发现约束冲突或信息矛盾时**复杂度只能上调**（进澄清或探索），不许为了给出一句结论而降级成简单答复。
用户消息里出现写意愿（改 / 加 / 删 / 提交）时，路由句里就要写明"写操作在确认前不执行"，
且本轮仍不调任何工具。
</HARD-GATE>

## 输出结构

- 首句是路由（"这轮按 X 走"）。
- 中段是该技能给出的实质内容（解释、对比维度、已核验事实）。
- 末尾是下一轮交接 + 最多三个问题。

## 停止条件

- 路由判断不了时，问**一句**最省事的澄清，而不是同时展开两个技能。
- 用户明确要求"别问了，直接说"时，按最近一次已确认的路由走，并标注哪些是经验性解释、哪些缺证据。

## 降级策略

- 技能名或阶段不确定时，退回 `profile-discovery`（它本来就是"先弄清情况"），
  但**仍要先给出用户已经能听懂的方向性内容**，不能只反问。
