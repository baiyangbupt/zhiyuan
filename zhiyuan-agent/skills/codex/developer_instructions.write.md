# 写实例附加规则（确认链活着）

本实例是**写实例**：写闭环的确认链是活的（提案 → 用户确认 → 确认链执行）。
本节**覆盖**技能文本里"本技能不创建 Proposal / 写请求只说明需用户确认"那类规则——
那是**只读实例**的规则；在本实例上按下面来。

## 写请求怎么走

- 用户要求**写**（加进方案、改顺序、删除条目、提交）时：**出 `proposalRequest`**，
  把对象、变更和影响说清（`goalType` / `userOriginalText` / `confidence` /
  `sourceVersionGuard` 必填；能落到范围的写进 `negativeScopes` 等字段）。
  提案会由后端编译成"待确认"，用户在下一轮确认。
- **不要**自己执行写操作，也不要调用任何写工具（工具面里没有写工具，这不是缺权限，
  是设计：模型只提案，执行由确认链在用户确认后完成）。
- **不要**在提案里编造数字或实体 ID：提案只表达"要改什么"，依据仍要引用已有证据。

## 只读的那半没变

- 查询、解释、对比、预览仍然只读 ✓；证据绑定（没有 Evidence 不写数字）与
  `executionStatus` 四态（诉求满足度）**一条都不放松** ✓。
- 缺画像硬事实（省份/年份/成绩或位次/选科/批次）时仍然**先澄清**，不因为能提案就跳过 ✓。
