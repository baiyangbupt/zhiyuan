# sessionDetailV2 移动端展示修复设计

## 问题

`sessionDetailV2` 工作台在移动端已经提供“对话 / 工作台”切换，但工作台内部仍沿用桌面布局：

- 候选专业明细使用接近桌面宽度的横向表格，小屏需要横向滑动，用户很难连续阅读专业、计划、历年分数和录取率。
- 学校名、专业名、标签和排序操作按钮容易挤在一行，长文本会撑破卡片。
- 顶部概览、筛选栏和草稿篮在小屏占用过多空间，影响候选列表可视区域。

## 修复目标

- 桌面端继续保留现有表格布局，不改变 PC 验证口径。
- 移动端把候选专业明细改成纵向信息卡，优先展示用户能理解和决策的信息。
- 移动端标题、标签、方案操作、筛选栏和草稿篮允许稳定换行，不出现横向撑屏。

## 实现方案

### 1. 候选专业移动端卡片

在候选专业条目中新增 `mobileMajorCard`，移动端展示：

- 专业名称
- 录取率与冲稳保
- 计划数、学制、学费、专业代码
- 选科要求
- 近三年录取人数、最低分、最低位次

桌面表格仍保留；在 `max-width: 768px` 下隐藏 `.majorTable`，展示 `.mobileMajorCard`。

### 2. 工作台小屏布局收紧

移动端样式调整：

- 顶部四个指标卡压缩 padding、字号和间距。
- 冲稳保 tab 横向滚动，避免挤压筛选入口。
- 筛选入口、排序字段、升降序按钮保持同一行的最小可用布局。
- 候选卡标题、标签、院校基础信息允许换行。
- 学校/专业组头部在移动端去掉学校名前重复的冲稳保标识，由右侧录取概率块统一展示梯度；学校名和优选、锁定、状态等标签放在同一标题区内，地域/属性信息单独一行。
- 方案卡主体和操作按钮允许换行，长专业名按词断行。
- 草稿篮宽度贴合屏幕，展开高度限制在视口内。

## 验证方式

基础验证：

```bash
git diff --check
```

移动端产品验证：

1. 使用 375px 或 390px 宽度打开 `/sessionDetailV2`。
2. 切到“工作台 -> 候选”。
3. 展开一个院校/专业组。
4. 确认专业明细不再出现横向表格，信息按纵向卡片展示。
5. 检查长学校名、长专业名、专业限制说明、标签不会撑出屏幕。
6. 检查学校/专业组标题栏中，学校名前不再重复展示冲稳保；学校名和优选等标签在同一标题区，录取概率和冲稳保提示稳定在右侧。
7. 切到“方案”，检查上移、下移、固定、删除按钮可操作且不挤压标题。
8. 展开草稿篮，确认草稿面板不超过屏幕高度且可滚动。

当前 `npx tsc --noEmit` 仍受仓库既有类型问题影响，不能作为本次移动端样式修复的完整通过门禁。
