# Changelog

## Unreleased

### Fixed

- 新增 `/session/workspace-state` 工作台轻量状态接口，返回摘要、候选池 summary、草稿、方案、审查和操作记录等工作台所需字段，并裁掉 `candidatePoolState.items` 等大体积候选明细，避免刷新场景继续传输完整 `PlanningStateDTO`。
- `/session/workspace-state` 在保持轻量的同时补回当前草稿/方案已引用候选的明细项，用于前端刷新后继续展示方案区录取率、推荐系数、专业热度、就业表现等字段，避免恢复全量候选池传输。
- 排序方案 `move / pin / unpin` 接口新增轻量动作响应 `OrderedPlanActionRes`，只返回排序态、审查摘要、操作日志等前端合并所需字段，避免方案微调接口继续返回 20MB+ 全量规划状态造成明显等待。

- 新增 `P0` 真实样本初始方案评估报告与只读评测测试：`InitialPlanEvaluationP0ReportTest` 改为直接读取现有 `planningState` 后在内存中仿真 `initialRecommendation + orderedPlan`，不再把大体积评测结果回写数据库；首轮 `P0` 报告已覆盖 `session 14/11/15/16/17/7` 六个真实样本，并确认当前 `majorGroup` 主链路基本稳定、`major` 模式在“保区供给不足”场景仍需专项优化。
- 新增 `P1` 高分样本执行方案文档，明确当前先采用“mock 型高分评测 -> 再补 live synthetic 链路”的双阶段策略；首轮高分样本优先聚焦 `HN-07A / SD-05A / GD-06A / HE-06A` 四个稳态样本，并把候选池供给计数列为必打指标。
