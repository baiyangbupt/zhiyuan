## 三、口径的两个坑（写下来，免得下次再踩）

1. **引用面必须排除归档副本。** 工作区里有 `.local-prod-3.0.2/`（旧生产部署的一份拷贝），它里面
   的 `major_compare_tool.py` 等**引用**了当前树里已经没用的符号。不排除它，候选会从 83 掉到 53，
   而原 A 批点名的 `fuzzy_match_major_name` / `fuzzy_match_school_name` 会被误判成“还在用”。
2. **引用面的文件集决定候选数**（83 / 96 / 82 都出现过）。所以任何“清单数字”必须连同口径一起引用；
   本清单的口径 = 全工作树文本文件（排除 `.git`/`.venv`/`node_modules`/`__pycache__`/`.runtime`/
   `.local*`/`target`/静态与二进制），引用面 10067 个文件。
3. **名录类文档会污染引用面，包括本清单自己**（本次踩到并实测）：本清单列举了全部候选名，于是
   每个名字都多出一处“文档提及”。把它算进引用面，候选会从 83 掉到 **1**。所以扫描器里写死了
   `EXCLUDE_FILES = {"2026-09-23-死代码普查清单.md"}`。要注意的是：文档提及是**声明性**的
   （“这个名字被讨论过”），不是**事实性**的（“这个名字被调用过”）——保守起见仍算引用
   （可能代表计划中的工作），但名录类文档必须排除自身，否则清单会自我失效。
