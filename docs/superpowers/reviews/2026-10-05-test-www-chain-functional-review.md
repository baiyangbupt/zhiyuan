## 一、结论与现场边界

当前**不能放行 `test-www` 的原生对话**。`test-www` 的 `/assistant-pc` 是标准测试入口，
而 C2/C3/C4 的隔离栈及拟部署代理针对另一个域名 `test-wwww`；不能用隔离栈/替身的绿灯宣称标准入口可用。
2026-10-05 的无凭证只读探针显示：

| 边界 | 现场证据 | 判断范围 |
|---|---|---|
| 公网入口 | `https://test-www.gaotuzhiyuan.com/` 为 200，`/assistant-pc/` 为 308 到 `/assistant-pc`；`test-wwww` DNS 不解析 | 只能证明前一个域名 HTTP 可达，不能证明已装 C2 配置 |
| 公网 `/ws/chat?chatSessionId=0` | 无票、带标准 Upgrade/Origin 请求返回 **404 HTML**；直连本机 Agent `:18091` 同类请求为 **403 text/plain** | 公网请求当前没有到达同一验票入口；缺少合法票，不能声称 101 或业务响应已验证 |
| 公网 `/gaotu-assistant-bot/inner/planning/1/session/state?chatSessionId=0` | **不带登录态返回 200、`code:0` 和 planning 状态数据**；直连 `:18090` 同样返回 200 | 已确认公开入口暴露了内网面，优先封堵。只测 `sessionId=0`，**尚未证明**能读取他人真实会话或跨租户数据；不要在共享数据上试探 |
| 本地监听 | `:18090/:18091/:18092/:3001` 与 `:18290/:18291/:18292/:3201` 均有监听；`:18291/health` 200，`:18090`、`:18290/actuator/health` 500，`:3201/` 404 | 监听不代表健康；两个栈/路径不能互相替代。健康 500 的具体根因未追查 |

`test-www` 的公开 `/inner` 返回成功数据是 **P0 访问面阻断**：先限制该公开路由并核查已有访问日志，
再进行带登录的 WS 验收。对话无响应的近端链路缺口是公网 `/ws/chat` 没有进入 Agent 验票路由；
仍须用登录浏览器 Network/代理日志排除构建版本、取票或其他并发原因，不能只凭匿名探针归因全部症状。

## 二、分数提示与功能进度

`zhiyuan-web/src/constants/directSession.ts` 把 `SKIP_PREFILL_FORM` 设为 `true`，从列表直接创建 `draft:true`
会话；`ChatSessionBizService.createEmptyChatSession` 明确不写 `userScoreDetail`，
`app/gateway/snapshot.py` 将缺少的 score/rank 标为 missing。因此**初次显示缺少分数是当前入口设计的结果**，
而不是成绩已填写却丢失的证据。现有 `saveScoreInfo` 出现在非 draft 的建会话路径，尚未看到针对同一空会话
“对话采集成绩 -> 权威校验并持久化 `userScoreDetail` -> 新快照/推荐生效”的闭环验收。
缺分数不应让普通澄清/帮助消息静默无响应；把成绩缺失与 WS 断链分开诊断。

| 能力层 | 已有证据 | 仍缺的用户可用性证据 |
|---|---|---|
| 运行时/事件/持久化 | A1/A3/A4/A5/A7 有实现和定向测试；C4 后续记录替身 + 真浏览器 contract **12 passed**，写模式 F07 后半/F08/F09/F13 **4 passed**，P2 库计数证明合同栈未双写 | `test-www` 真 Origin、真 Codex 的取票 -> WSS 101 -> 首事件 -> 终态 -> 刷新恢复；运行实例及前端 bundle 指纹 |
| 招生事实/证据 | B0/B1/B2 有合同及真栈局部样本；B3 查明并部分接入上游计划/章程；B7 做了若干真模型只读问答 | B3 的全年份/政策原文口径、专业级来源、B7 的 16 场景 x3/压缩恢复仍未关账；概率没有权威源时必须报不可用 |
| 比较、推荐、完整方案 | B4 的比较矩阵仅构造数据，**推荐/Rank/候选预览未接**；B5 只有深复制与摘要合同，**真实无副作用预览/生成/审查未做**；P2 的确认事务在指定合同栈通过 | 不能将“确认操作能写且幂等”外推为“用户能从画像完成比较、生成、预览、审查、正式方案” |
| 前端/公网 | A6 源码有统一事件和卡片，C4 替身真实浏览器测过部分交互 | `test-www` 当前 `/ws/chat` 404；页面仍从 `sessionDetail.ts` 发 `/inner/planning/...`；生产 `next.config.mjs` rewrite 没有 dev/test 的 `INTERNAL_PATH_GUARDS`；C5 报告/发布门禁/回滚未见完成证据 |

其中 C4 原报告末尾的 **3 passed / 3 failed** 是 9-26 当晚中间状态；后续评审入口及 9-28 台账记录了
contract 12 passed 与写路径四项全绿。口径仍是**受控栈**，绝非 `test-www` 公网回归。

## 三、现行计划修订（执行方按序）

原 A/B/C 架构和 C4 F01-F16 矩阵保留；改变的是**入口、门禁和排期**，不把历史计划改写为已完成。
`test-www` 作为用户正在使用的**标准测试入口**单独建验收轨；原计划 `test-wwww` 的隔离公网轨保留为未验，
在 DNS/TLS 与代理可用之前不能合并结果，也不能在 C2 配置上只替换域名就宣称部署成功。

1. **P0 公开访问面，先阻断再复测。** 由拥有 `test-www` 代理配置的执行方核对生效 vhost 的
   `/gaotu-assistant-bot/inner/` 规则，封闭 `/inner/`、`/internal/`、`/admin/`、`/debug/`；
   检查同一前缀的其他路由和已有访问日志，不做共享会话枚举。必须保证 Next production rewrite
   与代理两层都不能重新透传内网面；不能为了修工作台而放开它。证据：无凭证公开请求为 404/403，
   合法公开 chat/ticket 路由不回归；具体泄露范围若日志提示异常再按安全流程处理。
2. **P1 打通 `test-www` 的最短会话链。** 先记浏览器实际加载的 build id、`APP_ENV/basePath`、
   `NEXT_PUBLIC_CODEX_ACCESS_MODE` 和 runtime 指纹；从列表新建一个有成绩会话，按顺序记录
   创建会话 -> ticket HTTP 状态（不要记录票值） -> Upgrade **101** -> `turn.started`/进度/终态帧 ->
   前端回复与 Java 消息记录。代理补 `/ws/chat` 的授权配置与 Upgrade 后，还要用真实登录 Origin
   分别验证 Java/Agent 白名单；失败时定位到首个断点并附请求 id/脱敏日志。新构建及进程版本要相符。
   停止条件：合法票不能 101 或无票/错 Origin 可成功连接，均不可进入功能验收。
3. **P1 决定并实现空会话产品语义。** 建议保留“先对话”仅用于一般探索；未提供成绩时允许问清
   省份/选科/分数/位次，不承诺个性化推荐。若要从该会话继续填报，必须有同会话成绩补录的
   授权端点、校验、持久化和快照失效/重新取数；否则在使用依赖分数功能前明确引导到已有
   `/customerDetail` 表单建立**新的完整会话**，不得暗示已更新原会话。先由产品/业务负责人确认
   是否要求“同一空会话继续”，执行方据此拆开发版；不能仅删掉缺分数提示。
4. **P1 工作台访问面迁移。** 清点 `sessionDetail.ts` 所有浏览器 `/inner/planning/...` 调用，
   按读/写分别提供精确的、带登录与 tenant/session ownership 校验的公开 facade；对写请求维持
   Pending/CAS 和幂等规则，不给浏览器直通 inner。证据：跨用户/跨租户被拒，工作台合法查询和
   已授权动作成功，代理层 inner 一直被拒；特别对照生产 build 与 C4 的 dev/test 测试结果。
5. **P2 补功能主体再扩大场景。** B3 核清年份、政策原文与专业级来源；B4 接真实候选预览、
   比较/推荐与 Rank（分清概率与适配分）；B5 以“抽取计算且原写路径不回归 -> 数据库前后
   不变的预览 -> 审查内容不变”为检查点推进，再验证 P2 确认后的正式方案。真实来源不可用
   时展示限制，不造数；保持每项独立评审。
6. **P2/C5 放行门禁。** 复跑 C4 合同套件和写路径，完成 F01-F16 对应真实模型/上游与隔离写入
   测试；补 B7 的可见答案评价、恢复和性能实测。分别记录 `test-www` 与 `test-wwww` 的 DNS/TLS、
   匿名拒绝、登录取票、WSS 101、流式、缺分数/已知分数两类会话、确认/取消/冲突/刷新，
   C5 的 machine-readable 报告、checker 和回滚演练。`not_run`/环境失败计入未达标，
   不以纯单测、假模型或首页 200 代替公网放行。

执行方先回传 **P0 封堵证据 + P1 首断点定位**；完成一项更新对应报告/台账及版本指纹，
再进入下一项，不代替操作方改变共享代理或数据。计划需要的产品裁决仅第 3 项“同会话补录
还是表单新建”一处；在裁决前可独立处理第 1、2 项及 facade 的访问合同。
